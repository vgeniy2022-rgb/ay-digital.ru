### Черновики, файлы и безопасность

- Тот же IndexedDB `sitevl-studio`, версия БД 1, stores `projects` / `assets`. Схема проекта остаётся v1; необязательный `settings.catalogCustomizer` содержит только версию настройщика/шаблона и выбранные preset-параметры.
- Проект содержит метаданные и `asset://id`; файлы — отдельные Blob-записи. Новая фотография и обновлённый проект сохраняются одной транзакцией. Очередь автосохранения защищает от перезаписи черновика поздним завершением более старого сохранения. Ошибка записи видна, данные остаются на экране, доступна повторная попытка.
- Проверяются сигнатура файла, MIME, расширение, ненулевой размер: JPG/PNG/WebP/AVIF, до 12 MiB на входе и 32 MP после декодирования. SVG/GIF/HTML и переименованные файлы не принимаются. Существующий canvas-оптимизатор Studio ограничивает сторону 2200 px, выдаёт WebP (PNG fallback браузера), удаляет исходные метаданные файла.
- До 20 изображений / 40 MiB на черновик с учётом undo-истории. Каждая замена создаёт новый ID, поэтому undo возвращает настоящую прежнюю фотографию. При reload с Web Locks удаляются только неиспользуемые файлы именно этой копии; до reload они сохраняются для undo. Blob URL освобождаются при закрытии экрана.
- В браузерах с Web Locks вторая вкладка ждёт закрытия первой. Без этого API автоматическое удаление файлов отключено; следует работать с черновиком в одной вкладке.
- Фото, текст и JSON не отправляются на сервер; Gemini не вызывается. Локальный ID черновика исключён из Visitor Intelligence перед fetch; публичная аналитика остаётся работающей. Нет ввода произвольных CSS/JS; текст выводится React как текст. Маршрут помечен noindex и не добавлен в sitemap.
- Хранилище привязано к браузеру и origin. Очищение данных браузера удалит черновики. Автосохранение не является облачной резервной копией; undo-история живёт только до reload.
