# Каталог → заявка владельцу (этап 4)

## Интеграция

- Тот же `POST /api/ai-leads`, новый allowlisted `source=template-catalog`: `prepare` → отдельные бинарные `upload` → `finalize`. Старый AI-контракт не заменён.
- Существующий Redis REST клиент и настройки. Атомарная финализация Lua сохраняет полную Studio schema-v1 копию, метаданные фото, контакт/пожелания, версию дизайна, пакет и цену из **общего прайса**, время, безопасную рекламную метку. Дизайн пользователя не перезаписывает исходный шаблон.
- `scripts/generate-template-contract.ts` генерирует серверный allowlist из всех опубликованных проектов (30 после этапа 7) и `priceDirections`; выполняется при build. `_templateContract.generated.mjs` не редактируется вручную и не является вторым источником цен.
- Фото проходят повторное декодирование, проверку хеша/размера/числа пикселей и конвертацию в WebP без EXIF. До 20 файлов, до 3 МиБ на бинарный HTTP-запрос, до 40 МиБ всего, до 32 Мп входного изображения / 2200 px после обработки. JSON до 200 КБ. SVG, анимация, внешние image URL, произвольные Puck-компоненты, CSS/JS и base64 в Redis не принимаются.
- Rate limit: до 5 новых отправок / 30 минут на хеш доверенного IP Vercel; общий предохранитель 100 / 24 часа (скользящий TTL). Сырые IP не записываются. Клиентская capability для конкретной отправки передаётся заголовком, хранится на сервере только хеш. ID не даёт доступ к данным. Повтор завершённой отправки не создаёт второй lead/уведомление.
- Telegram: существующий бот, краткое сообщение `Заявка SITEVL · каталог дизайнов`. Отправка уведомления best-effort после сохранения. Сбой Telegram не отменяет сохранённый lead; статус хранится отдельно. При аварийном завершении функции между сохранением и Telegram автоматического повторного уведомления нет (защита от дублей); владелец может открыть сохранённую заявку. Это не гарантия exactly-once доставки стороннего сервиса.

## Доступ владельца

Ссылка `/templates/owner/<lead UUID>` из сообщения. Это **одна закрытая заявка**, не публичный список/CRM. Ввести существующий `VISITOR_OWNER_API_TOKEN` в password-поле. Значение остаётся в памяти вкладки, передаётся Bearer-заголовком в существующий `/api/visitor-owner`, не помещается в URL, localStorage, пакет или журнал.

- `GET /api/visitor-owner?view=template-lead&leadId=…` — полный проект/контакт без адресов приватного Blob.
- `GET /api/visitor-owner?view=template-asset&leadId=…&assetId=…` — только файл именно этой заявки, за той же авторизацией. Произвольные пути/URL не принимаются.
- Viewer получает и проверяет реальные байты всех фото, затем воспроизводит документ существующим `DesignFrame` / `StudioRenderer`. Нет внешних отправок из демонстрационных форм.
- «Скачать полный пакет» использует существующий Studio `createOwnerBundle`: project.sitevl.json, contact.json, assets.json и файлы assets/. Публичные исходные фотографии остаются обычными ссылками проекта; загруженные пользователем фото включены в пакет. Ключа доступа в пакете нет.
- Кнопка «Закрыть доступ» убирает данные и object URLs; reload требует повторной авторизации. Noindex, nofollow, no-store, исключение из visitor telemetry; технические маршруты не добавляются в sitemap.

## Настройка (без передачи секретов в чат)

Локальная проверка обнаружила **отсутствие** перечисленных runtime-настроек в локальных env-файлах. Production-переменные в этом этапе не проверялись и не менялись.

1. В **существующем** Vercel project SITEVL открыть Storage → Create Database → Blob → выбрать **Private**. Не использовать Public store и не создавать новую Redis database. [Официальная документация Blob](https://vercel.com/docs/vercel-blob/using-blob-sdk).
2. Подключить этот private store к тому же проекту. Серверу нужен `BLOB_READ_WRITE_TOKEN` от закрытого store.
3. Сохранить/проверить существующую пару `AI_LEADS_REDIS_REST_URL` + `AI_LEADS_REDIS_REST_TOKEN` **или** `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` **или** `KV_REST_API_URL` + `KV_REST_API_TOKEN`. Не смешивать разные базы.
4. `VISITOR_OWNER_API_TOKEN`: существующий закрытый ключ доступа владельца. Использовать длинный случайный секрет. Не распространять ссылку вместе с ключом.
5. Для существующего бота: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Поддержан прежний fallback `AI_LEADS_TELEGRAM_*`. Новый бот не требуется.
6. Необязательно `AI_LEADS_RETENTION_DAYS` (90 по умолчанию, 7–365). Существующий `VISITOR_ATTRIBUTION_SECRET` сохраняется: подписанные рекламные метки имеют приоритет над браузерным `src`. Cookie, полный referrer/query и raw UA не сохраняются в новой заявке.

Все значения — **только server-side**, никогда `VITE_*`. Для локального полного runtime использовать Vercel local runtime с Development-переменными (обычный Vite не исполняет `api/*.mjs`). Не перезаписывать существующий env-файл массовым pull. Этот этап не запускает deploy.

`GET /api/ai-leads` сохраняет старые поля и добавляет `templateCatalog: { configured, storageConfigured, filesConfigured, ownerConfigured }`. Это проверка присутствия конфигурации, **не live-проверка работоспособности провайдеров**. Неверный ключ/публичный вместо приватного store приводит к отказу загрузки, без ложного успеха.

## Хранение и удаление

- Существующие `sitevl:ai-lead:<UUID>` и `sitevl:ai-leads:index` — сохранённые заявки и закрытый индекс (максимум 1000 ссылок).
- `sitevl:ai-leads:template-upload:<submission UUID>` — подготовленный снимок/хеш capability/зарегистрированные фото, 24ч до завершения, затем тот же TTL что у заявки.
- `sitevl:ai-leads:template-notification:<lead UUID>` — статус уведомления, TTL заявки.
- `sitevl:ai-leads:template-expiry` — очередь сроков удаления файлов; `…:cleanup` — краткоживущая блокировка. `sitevl:ai-lead-rate:template:*` — rate limits.
- Blob: только `template-leads/<submission UUID>/<asset ID>.webp` с `access: private`; служебные URL/пути хранятся server-side. Redis не содержит байтов изображений.
- Redis удаляет данные по TTL. Бинарные файлы удаляет `cleanupTemplateUploads`: не более двух просроченных отправок при следующем prepare, после дополнительного часа запаса. При отсутствии новых заявок или недоступности Blob файлы **не удаляются точно в момент TTL**. Для гарантированного срока владельцу потребуется отдельно запланированный вызов этой серверной функции; cron/daemon на этом этапе не создавался. Очередь сохранена для повторной попытки. Функция не затрагивает другие Blob prefixes и существующие LAB/AI/visitor namespaces.
- При добровольной отправке существующий visitor/session связывается с lead; история получает `/templates/<slug>`, не `/ai-website`. Подписанный ad cookie имеет приоритет, затем существующая bound session, затем ограниченный browser tag с явной пометкой `unverified`.

## Границы QA

Автотесты используют отдельный временный Redis с Unix socket, без TCP/production credentials, и тестовые адаптеры private files / Telegram. Реальные клиентские заявки не читаются и не удаляются. Реальный Vercel Blob upload, получение Telegram на устройстве и production owner view требуют перечисленных настроек и отдельной разрешённой публикации. Локальный PASS не заменяет такой live PASS.
