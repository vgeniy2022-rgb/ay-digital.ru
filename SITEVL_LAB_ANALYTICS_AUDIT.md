# SITEVL LAB Analytics — аудит реализации

Дата аудита: 4 сентября 2026 года.

## Границы задачи

Проверена существующая реализация анонимной статистики SITEVL LAB. В проекте оставлен один API endpoint (`/api/lab-stats`), один клиентский analytics provider и один набор Redis-ключей. Новая база Redis не создавалась, существующая архитектура сайта и дизайн LAB не переписывались.

## Состав данных

Система хранит только агрегаты и случайные технические идентификаторы:

- глобальное число посещений LAB;
- множество анонимных visitor ID для подсчёта уникальных посетителей;
- HASH со счётчиками запусков пяти публичных экспериментов;
- временные ключи дедупликации с TTL;
- временные ключи ограничения частоты с TTL.

IP-адрес, fingerprint, точная геолокация, имя, телефон, email и содержимое действий внутри экспериментов не записываются. Клиент не может передать имя Redis-ключа: сервер принимает только два строго описанных события и проверяет experiment ID по закрытому allowlist публичного каталога.

## API и Redis

`GET /api/lab-stats` отдаёт только публичную агрегированную схему: `visits`, `uniqueVisitors` и счётчики разрешённых экспериментов. `POST /api/lab-stats` принимает только JSON размером до 4096 байт.

Используются существующие server-side переменные окружения Vercel/Upstash. Ни Redis URL, ни REST token не передаются клиенту. Проверка production bundle `dist` не обнаружила имён серверных Redis-переменных.

Счётчик посещений увеличивается атомарной Redis-командой `INCR`; уникальность — `SADD`/`SCARD`; запуски — `HINCRBY` в одном компактном HASH. Повтор одной сессии блокируется `SET ... NX EX`, повтор одного события запуска — отдельным `SET ... NX EX`. Ограничение — не более 30 событий в минуту на анонимную сессию, дополнительно проверяемое в памяти функции и Redis.

При недоступном Redis endpoint возвращает общий `503` без внутренних деталей, а LAB продолжает отображаться со статусом временно недоступной статистики.

## Клиент и интерфейс

Постоянный случайный visitor ID хранится в `localStorage` под ключом `sitevl-lab-visitor-id`. ID текущей вкладки и маркер уже принятого посещения хранятся в `sessionStorage`. Маркер выставляется только после успешного ответа API, поэтому временный отказ хранилища не приводит к ложной отметке успешного учёта.

На главной LAB показаны компактные глобальные показатели с русским форматированием чисел. TOP-3 строится только из реальных счётчиков и названий текущего публичного каталога. Если запусков нет, блок не создаёт фиктивный рейтинг.

Локальная responsive-проверка выполнена на ширинах 320, 375, 390, 430, 1024, 1366, 1440 и 1920 px. Горизонтальный overflow не обнаружен. Состояния loading, unavailable и заполненная статистика отображаются без падения страницы; ошибок браузера не обнаружено.

## Остаточный риск

Это лёгкая продуктовая аналитика, а не финансовый журнал: при редком аварийном завершении функции между установкой dedup-ключа и последующим `INCR` возможно недосчитывание одного посещения. Повторный учёт при retry исключён. Для заданного уровня статистики такой компромисс принят осознанно и не требует Lua-транзакции или отдельной базы.

Фактическая проверка production Redis, публичного deployment и production UI фиксируется в `SITEVL_LAB_ANALYTICS_REPORT.md` после публикации.
