# Аудит SITEVL AI Website Generator

Дата проверки: 2026-09-03

## Результат аудита до реализации

- В проекте уже существовал serverless endpoint `POST /api/ai` с Gemini, server-only `GEMINI_API_KEY` и моделью `gemini-3.5-flash-lite`.
- Endpoint уже использовался SITEVL Studio и Modern OS. Новый параллельный AI endpoint не создавался.
- В production Vercel переменная `GEMINI_API_KEY` присутствует как Secret только в окружении Production. Значение не читалось и не выводилось.
- Публичного генератора концепции сайта не было. Старый конструктор `/lab/builder-legacy` относится к LAB, использует локальные черновики и не является системой публичных лидов.
- Источник коммерческих цен уже существует в `src/data/priceDirections.ts`; новую независимую матрицу цен создавать нельзя.
- До этой задачи публичная форма не принимала и не сохраняла персональные данные, что было прямо указано в политике конфиденциальности.
- В проекте не обнаружено подключённого закрытого server-side хранилища заявок. Текущие production variables не содержат Redis/KV/Postgres/Supabase/Blob-конфигурации.
- Авторизованной панели администратора для просмотра персональных данных нет. Поэтому публичный или скрытый admin route не добавлялся.

## Проверенные границы безопасности

- Gemini получает только ограниченный prompt длиной до 6000 символов и компактный allowlisted context.
- AI не может вернуть исполняемый сайт: разрешён только JSON версии 1.
- Ответ проходит server-side разбор, allowlist типов, очистку строк и ограничения количества элементов.
- При первом невалидном ответе выполняется одна попытка ремонта через Gemini; после второго отказа возвращается честно помеченный безопасный детерминированный fallback.
- Renderer использует React-компоненты и текстовые значения. `dangerouslySetInnerHTML`, `eval`, `Function` и динамическая загрузка AI-кода отсутствуют.
- URL существующего сайта не загружается сервером автоматически. Пользователь сам вставляет разрешённый к анализу текст; это исключает SSRF и не обходит robots/access controls.
- AI не генерирует отзывы, клиентов, награды, адреса, телефоны, реквизиты или юридические сведения. Для неподтверждённых контактов используются явные placeholders.
- До трёх генераций разрешено на анонимную session id. При подключённом Redis лимит дублируется server-side с TTL 30 минут.
- IP, геолокация, fingerprint и User-Agent не записываются в lead record.
- Ключ Gemini, Redis token и Telegram bot token доступны только serverless functions и не имеют префикса `VITE_`.

## Release-gate

Первичная проверка выявила отсутствие обязательных server-side переменных. 2026-09-03 к Vercel Production/Preview подключена стандартная KV REST-пара:

- `KV_REST_API_URL`
- `KV_REST_API_TOKEN`

Вместо собственных имён подходит стандартная полная Vercel/Upstash-пара `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` либо `KV_REST_API_URL` / `KV_REST_API_TOKEN`.

Backend поддерживает эту пару напрямую. Значения не выводились, не копировались во frontend и не добавлялись в Git. После production deployment подтверждены `configured:true`, запись двух безопасных QA-лидов, чтение закрытой записи владельцем и TTL около 90 дней.

Release-gate завершён: redeploy, `configured:true`, реальный Gemini-запрос, безопасная тестовая заявка, подтверждение закрытой записи и production browser QA выполнены 2026-09-03.
